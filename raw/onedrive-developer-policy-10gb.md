> **一个月前，我把微软开发者订阅写成了“零成本25TB硬盘”。评论区很快指出：开发者租户已经被限制为300GB，旧E3也在退出。质疑是对的。微软最新规则比后台那个5TB数字更重要。我重新查完官方文档，也重新读取了自己的租户：5TB还显示着，但真正能依赖的边界只剩10GB。**

先把话放在前面：

**我之前那篇《你花天价加硬盘，我零成本25TB OneDrive白养虾》，关于开发者订阅容量的判断已经过时，而且有一处根本性错误。**

我把后台能看到的容量、商业版的扩容规则和免费开发者沙盒混在了一起，最后写成了“微软E3开发者订阅白给25TB”。

这个说法现在不成立。

评论区有人直接问：

> 作者不知道微软已经把开发者账号限制到300GB了吗？

还有人提醒，旧E3开发者订阅正在退出，不应该再拿控制台里的到期时间当长期保证。

这些质疑没有必要绕过去。政策发生了变化，我之前也没有把不同许可证的边界拆清楚。现在重新核一次。

## 微软现在到底给多少空间

微软在最新的 Microsoft 365 Developer Program FAQ 里已经写得很直白：

- 纯开发者租户的共享存储上限是 **300GB**；
- Developer SKU 在混合许可证租户中贡献的 SharePoint 存储是 **0GB**；
- Developer SKU 用户的 OneDrive 上限是 **10GB/人**。

【官方文档】https://learn.microsoft.com/en-us/office/developer-program/microsoft-365-developer-program-faq

这三个数字不能混在一起。

**300GB不是“每个人有300GB”。**

它是纯开发者租户的共享存储上限，主要约束SharePoint与租户池。真正落到Developer用户OneDrive上的官方限制，是10GB/人。

所以，“微软把每人的25TB降成300GB”也不够准确。

更准确的说法是：

> **免费开发者租户不再适用商业E3/E5的常规存储预期。当前公开规则是租户共享300GB，Developer用户OneDrive 10GB。**

![开发者OneDrive新旧认知对比](/images/onedrive-developer-policy-10gb-cover.webp)

## 那我后台为什么还显示5TB

我没有只看文档。

2026年8月21日，我重新通过 Microsoft Graph API 读取了自己的租户。

结果如下：

```text
SKU：DEVELOPERPACK
SKU状态：Enabled
许可证：25个
已分配：3个
OneDrive类型：business
配额状态：normal
后台配额：5120 GiB
已使用：78.770 GiB
回收站：9.368 GiB
剩余：5031.861 GiB
```

也就是说，后台现在确实还给我返回5TB，状态也仍然是normal。

但这次我不会再把这个数字直接写成“微软送了5TB”。

**Graph API返回的是当前技术配置。官方FAQ定义的，才是微软现在愿意为Developer订阅承担的权益边界。**

两者冲突时，做长期资产规划不能赌后台字段一直不变。

我的账户已经用了78.77GB。它低于300GB租户共享上限，却明显超过10GB单用户限制。现在还能上传，只能证明策略还没有完全落到这个账户，或者后台仍保留旧配额。

它不能证明5TB会一直存在。

这也是这次最关键的判断：

> **5TB数字还在，5TB权益已经不能信了。**

## 25TB是怎么来的

旧文里最误导人的一句，是“5TB用满后联系微软支持，可以拉到25TB”。

这句话来自过去的商业企业订阅扩容规则和历史经验。但微软当前公开的 OneDrive 服务说明，只明确写了：

- Microsoft 365 E3：1TB/人，可提高到5TB；
- Microsoft 365 E5：1TB/人，可提高到5TB；
- 更高的企业存储需求，需要与微软代表协商。

【官方文档】https://learn.microsoft.com/en-us/office365/servicedescriptions/onedrive-for-business-service-description

现行页面已经没有公开承诺：

> 用到5TB的90%，提交工单就一定获得25TB。

更重要的是，这份服务说明描述的是商业订阅，不是免费开发者沙盒。

开发者订阅有自己单独的FAQ和条款。拿商业E3/E5的容量页面去解释Developer SKU，本身就是错位。

所以现在必须拆开看：

| 类型 | 当前公开存储规则 | 能否当生产存储 |
|---|---|---|
| 商业 Microsoft 365 E3/E5 | 1TB/人，可提高到5TB | 按商业合同和许可证使用 |
| Microsoft 365 Developer | 300GB租户共享，10GB/人 | 不能，仅限开发测试 |
| 后台仍显示5TB的旧开发者账户 | 当前技术字段，不是长期承诺 | 不能据此规划长期资产 |

过去能改到5TB，不代表今天仍有5TB的使用权。

过去有人成功拿到25TB，也不代表Developer用户现在还能复制。

## 开发者订阅本来就不是私人网盘

这不是我给政策找补，而是微软条款原文。

Microsoft 365 Developer Program 的使用条款写明：服务用于设计、开发和测试应用，**不能用于生产环境**。

【官方条款】https://learn.microsoft.com/en-us/office/developer-program/terms-and-conditions

最新FAQ还补了几层限制：

- 25个用户许可证只供开发测试；
- 是否续期取决于有效的开发活动和资格；
- 人为制造的非开发活动可能不算续期依据；
- 微软可能要求开发者租户每90天重建；
- 数据和配置应始终备份到租户之外。

这意味着，开发者OneDrive最合理的定位从来不是“永久免费的私人云盘”，而是：

> **一块随时可能失去的开发测试空间。**

可以放测试数据、样例文件、自动化验证产物。

不能放唯一副本，不能承担生产备份，也不能把后台显示的容量当成资产。

我之前让自动化系统把它当异地备份目的地，技术方案本身能运行，但对Developer订阅的定位判断错了。

现在我会把它降级为可丢弃副本。真正的完整备份仍留在自己的存储设备和其他独立位置。

## 旧E3是不是9月14日全部消失

评论区另一个争议，是“所有E3开发者订阅将在2026年9月14日统一删除”。

能确认的事实有这些：

- Office 365 E3 Developer从2018年开始提供；
- 2019年9月起，新用户改发Microsoft 365 E5 Developer；
- 现在新用户不能选择E3；
- 微软提供从旧E3迁移到E5的路径；
- 删除旧E3并创建替代E5后，旧租户保留60天用于迁移。

【官方文档】https://learn.microsoft.com/en-us/visualstudio/subscriptions/vs-m365

至于“全球所有旧E3都在9月14日统一删除”，我查到的是第三方转述、社交媒体帖子，以及部分账户显示在9月13日或14日前后到期。

我没有在微软公开的开发者FAQ、产品生命周期目录或Tech Community公告中，找到一份明确写着“所有旧E3租户统一于2026年9月14日删除”的正式原文。

所以这里不能装作已经坐实。

我的判断是：

> **旧E3的退出风险是真实的，但统一清退日期应以每个租户收到的邮件、消息中心通知和Developer Program仪表板为准。**

手里还有旧E3的人，不必等互联网争论出统一答案。既然微软已经停止向新用户提供E3，也明确给了E3迁移到E5的路径，重要数据现在就该导出。

## 如果订阅真的失效，还有多久

微软当前FAQ给出的标准生命周期是：

- 订阅过期后，前30天用于迁移数据；
- 接下来的30天只有管理员能访问；
- 到第60天，订阅和数据会被删除。

这不是让人等到最后一天的缓冲券。

租户一旦进入只读、资格失效或后台重算，批量下载、权限恢复和跨租户迁移都可能比想象中麻烦。

最稳的做法不是猜微软哪天动手，而是趁现在还能正常读取，把数据先拿回来。

## 我现在怎么处理这78.77GB

我不会立即删除所有东西，也不会继续往里面堆。

处理顺序很简单。

### 先停止增长

关闭把Developer OneDrive当长期备份盘的任务，避免每天继续写入。

如果你也在跑自动备份，先检查定时任务、同步客户端和服务器脚本。不要只看网页端有没有手动上传。

### 再做租户外副本

优先导出这几类数据：

- 只有这一份的文件；
- 无法重新生成的照片、文档和项目资料；
- 自动化系统依赖的配置与密钥备份；
- SharePoint站点和团队文件；
- 邮箱、日历及其他与租户绑定的数据。

我的做法是让本地存储保留完整主副本，云端只承担第二或第三副本。

### 最后把使用量压下来

官方对Developer用户写的是10GB，不是78GB，也不是300GB。

因此最终目标应该是把单个Developer用户的OneDrive压到10GB以内。300GB只能作为租户共享池的另一个边界，不能替代单用户限制。

如果暂时来不及全部迁完，至少先确保整个开发者租户低于300GB，并持续观察管理中心是否出现只读或“Trial-only tenants”警告。

## 怎么判断自己是哪一种账户

别再只看“E3”“E5”三个字符。

你至少要检查四处：

1. Microsoft 365管理中心里的产品名称和SKU；
2. Developer Program仪表板里的订阅状态；
3. SharePoint管理中心的租户存储警告；
4. OneDrive实际配额与已用空间。

如果你看到的是Developer、DEVELOPERPACK、E5 Developer或开发者沙盒，就按300GB租户共享和10GB/人的当前规则做准备。

如果你持有付费商业E3/E5，则查看商业许可证合同和OneDrive服务说明，不要套开发者规则。

如果你持有旧E3 Developer，立即检查管理员邮箱、消息中心和Developer Program仪表板。不要只相信控制台某个页面上的到期日期。

## 这次真正改掉的判断

旧文的上传优化仍然有效：Client Credentials Flow、5MB分片、直连和重试，都是可以复现的工程方法。

失效的是它建立在上面的前提：

> “开发者订阅是一块永久、稳定、可扩到25TB的免费硬盘。”

这个前提已经被官方新规则推翻。

所以我保留技术方案，撤回容量承诺。

也不再推荐任何人为了存储去购买所谓的“老E3开发者号”。旧E3正在退出，Developer本身也不是生产存储许可证。买来的不是传家宝，而是一项无法控制的租户风险。

一句话收口：

> **后台容量是现状，官方条款才是边界。看到5TB可以高兴，但绝不能把唯一的数据押在上面。**

> 「每天帮你踩一个 AI 的坑，省下一小时。」

你现在的开发者OneDrive显示多少？如果已经出现300GB或只读提示，把实际情况留在评论区。
